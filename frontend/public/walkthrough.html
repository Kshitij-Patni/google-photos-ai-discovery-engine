01 · The problem

Search works when you know what to type. Memory doesn’t work like that.

Users know a photo exists but have forgotten the date, place, album or the right keyword. Human memory is associative and emotional; retrieval is keyword-driven. The engine measures that gap at scale.

What the user remembers“That small café on our Goa trip.”

A café, a trip, the visual scene, roughly “last year”.

What they’ve forgottenEverything searchable

Exact date, place name, who was in it, which album, the keyword the index uses.

🧩

Understand

How people remember old photos — which cues they hold on to.

🔎

Identify

Where the retrieval experience breaks in the user journey.

📊

Quantify

Frequency and severity of every problem type.

🎯

Prioritise

Opportunity score = impact × frequency × feasibility.

Strategic goal: increase the share of users who successfully retrieve a photo they remember but can’t precisely describe when they start searching.

02 · How it works

A 9-phase AI pipeline, from scraping to insights

One orchestrator (src/pipeline_runner.py) runs every phase in order, with checkpoints and resumable runs (--full-run, --analysis-only, --from <phase>).

Raw records collected
15,275
After clean + dedupe
6,754
Relevant to retrieval
5,682
Classified into archetypes
5,012
1

Ingestion — 4 public sources

Scrapers for Google Play Store (9,847), YouTube comments (3,559), Apple App Store (1,850) and Google support forums (19), spanning 2016 → Sep 2026. Everything is normalised to one schema. src/ingestion/*

2

Clean → De-duplicate → Relevance filter

Text cleaning, near-duplicate removal, then an LLM relevance classifier (3,676 relevant + 2,006 partially relevant of 6,754). src/preprocessing/*

3

Metadata enrichment — 16 fields per record

Photo category, memory cues remembered/forgotten, search strategy, outcome, frustration level, and more (5,669 enriched, 0 failed). metadata_enricher.py

4

Archetype classification

Each record is mapped to one of 8 predefined retrieval-problem archetypes (Gemini; Groq variant for speed/fallback). archetype_classifier*.py

5

Deep analysis — sentiment, journey, themes

Polarity / urgency / effort / emotion per record; a 6-stage search-journey model (Trigger → Formulate → Search → Evaluate → Refine → Abandon); and BGE-embedding + HDBSCAN clustering (labelled by Gemini) for emergent themes. sentiment_analyzer.py · journey_mapper.py · theme_discoverer.py

6

Correlations & user segmentation

Mutual-information / Cramér’s V factor importance (frustration, strategy and sentiment drive failure most) and K-means personas (silhouette-optimal k = 3). correlation_engine.py · user_segmenter.py

7

Root-cause synthesis & opportunity sizing

Root-cause chains per problem, headline stats, and recommendations for user research. insight_synthesizer.py

8

Hybrid RAG stores

A structured SQLite store for counts/aggregations and a ChromaDB vector store (BGE embeddings) for quotes and semantic search. A Gemini query router sends each question to SQL, vectors, or both. src/rag/*

9

Reports, charts & API

Archetype report, opportunity matrix, emergent-themes report, 10 interactive Plotly charts — all served through a FastAPI backend to the Next.js dashboard. src/output/* · src/api/*

05 · Key findings

What the evidence says

Numbers come from the pipeline reports in reports/ and the live API.

69.8%

Overall failure rate. Among users whose outcome is known, nearly 70% did not find the photo they were after (1,612 “not found” vs 718 “found”).

46%

High or extreme frustration. 2,259 high + 356 extreme out of 5,682 relevant records. Anger is the most common emotion (905), ahead of joy (721).

1 → 2

Organisation is the top problem. Album Fragmentation and Volume Overwhelm together account for ~20% of all feedback and score highest on opportunity.

59–73%

Every search strategy fails. Album browse 73% not found, keyword search 67%, people search 69%, timeline scroll 61%, location search 59%.

08 · Run it yourself

Local setup in a few commands

Backend & pipeline

# one-time setup
python3 -m venv venv && source venv/bin/activate
pip install -r requirements.txt
# .env → GOOGLE_API_KEY, YOUTUBE_API_KEY

# run the pipeline
python src/pipeline_runner.py --full-run
python src/pipeline_runner.py --analysis-only
python src/pipeline_runner.py --from vector_store

# start the API (http://localhost:8000/docs)
uvicorn src.api.main:app --reload --port 8000

# terminal Q&A
python src/output/interactive_qa.py

Frontend

# from /frontend
npm install
# optional: point at your own API
export NEXT_PUBLIC_API_URL=http://localhost:8000
npm run dev
# → http://localhost:3000
The Explore page calls an LLM through the backend, so the first answer can take a few seconds.
